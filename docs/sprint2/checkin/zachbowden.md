More specifically, I have learned how the API and the front end do NOT act like a traditional API backend and website front end. This is because the API backend gets addressed directly from the front end as a whole unit of the website, instead of a traditional API which would be a different URL for the backend and the frontend. For instance, my service which I wrote has an API on api.example.com, which is for my front-end at example.com. This is different from how tRPC works, where the web app calls the backend as if it were functions instead of a REST endpoint.
