	This sprint, I was working on implementing on the feature for an adminstrator to be able to enforce two factor authentication for all existing users on the team. This requries an admin toggle, which is only visible to admins, not users. Also, when a user without 2FA logs in, the user should get a pop up that walks them through the 2FA setup. There should be no way for the user to get rid of the toast, making the 2FA required. Additionaly, new accounts can't finish signing up until 2FA is set up. However, looking into the issue more, this crosses every layer. This issue likely needs to be split into smaller subissues. One issue could be storing the setting and adding the admin toggle. Another issue could be adding the required 2FA to sign up. One thing I have learned is to study the code before desiging a new feature. A popup alone can not enforce a security rule, because users could get around it by going to a different page. The check also needs to happen on ther server side. Analying the code first is important because it changes the scope and design. One thing I want to do differntly is update the issue whenever a design decision could change its acceptance criteria. I want to record decisions like whether Google sign in users are exempt from 2FA in the issue itself.
