	This sprint, I implemented the Event Favorites feature, allowing users to star and pin their most-used event types to the top of their dashboard. This issue was changed to two sub issues that were both completed in this sprint to complete the implementation. The first subissue created the database that would store the events that were favored. This includes the Prisma schema, SQL migration, and Repository class. The second subissue was focused on the tRPC endpoints and UI. As for what remains, there was an issue I was originally going to tackle for Sprint 1 but was pushed because of the complexity of the Event Favorites feature. This feature is a website setting to force all users to enable two factor authentication. One thing I learned about the codebase was that a request is made through 4 layers. First, the user clicks the star in the UI, which sends a request to the API layer. The API layer has the business rules, after which it calls the repository. The repository holds the database queries, such as create and delete. Finally, the repository accesses the database. One thing I would do differently for Sprint 2 is to take a little more time when assigning story points. At first, the Event Favorites feature was assigned 5 story points by itself, because we just assumed that it would require a small schema and UI change. At that point, we did not realize the complexity of making a request in the code base. Next time, we will take into consideration the architecture and established conventions of the codebase to more accurately assign story points.
